# Сумма заключённых договоров

Факт: полное поле Bitrix `OPPORTUNITY` для договоров, уже учитываемых
отделом продаж. `paid_at` — поле `UF_CRM_1744372636`, дата входа в стадию
«Полная / частичная оплата». Период определяется в Europe/Moscow.
Сохраняются воронка 34, отбор по составу отдела и устранение копий из
`20261113_rop_dedup_copies.sql`. Текущая стадия сделки не ограничивается.
Все продукты входят один раз; позиции, депозиты и платежи отдельно не суммируются.

План `договоры_сумма` задаётся менеджеру на календарный месяц. За неполный
месяц учитывается доля календарных дней. За период из нескольких месяцев
складываются эти доли. План отдела равен сумме планов менеджеров. Пустое
поле означает отсутствие плана, 0 — явно заданный нулевой план.
Планы ушедших сотрудников остаются видны за месяцы, где они были заданы.

## Порядок выпуска

1. В проекте Supabase `jgmuuehxavwlrfkonnzx` применить
   `supabase/migrations/20261119_rop_contract_amounts.sql`.
   Миграция транзакционная, не меняет строки договоров или ранее заданные планы,
   добавляет агрегатную витрину и разрешает новый ключ метрики.
2. Выполнить проверку ниже. Она возвращает только агрегаты, без клиентов.
3. Выпустить проверенный commit на Vercel в проект
   `prj_5LjfMs1KQcdpSyd6jhKT8ARuGz50`, команда `team_EARcd06q81jNU3ia6A9ZQ7IG`.
   Сборка: `npm run build`, каталог результата `dist`.
4. В авторизованном кабинете проверить выбранный месяц: количество договоров
   из новой витрины равно действующему итогу, сумма главной равна сумме менеджеров,
   планы сохраняются. Проверить кабинет РОПа и вкладку администратора.

```sql
with old_counts as (
  select дата, отдел, sum(окс_всего) as contracts
  from public.rop_daily group by 1, 2
), new_counts as (
  select дата, отдел, sum(договоров) as contracts,
    sum(сумма_договоров) as amount,
    sum(договоров_без_суммы) as missing
  from public.rop_contract_amounts group by 1, 2
)
select count(*) filter (
    where coalesce(o.contracts, 0) <> coalesce(n.contracts, 0)
  ) as days_and_teams_with_count_mismatch,
  coalesce(sum(n.missing), 0) as contracts_without_amount
from old_counts o full join new_counts n using (дата, отдел);
-- days_and_teams_with_count_mismatch должно быть 0.
```

## Проверки

`npm test`: расчёт периода и планов, копии, отсутствие даты оплаты, все продукты,
московская граница месяца, права anon/authenticated и фильтр по отделу;
SQL выполняется в локальном PostgreSQL (PGlite) на вымышленных данных.

`npm run test:ui`: Chrome, оба режима приложения, денежный план/факт,
менеджер без продаж, создание/изменение/удаление плана, невалидный ввод.
Все API-запросы перехвачены и используют вымышленные данные.

`npm run build`: production-сборка Vite.

Выпуск на production разрешён только после успешного применения миграции.
При откате интерфейса новая витрина и новый ключ планов совместимы со старым кодом;
денежные планы удалять не требуется.
